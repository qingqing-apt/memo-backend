# 第四天：Agent 评测与优化记录

> 基于第三天已运行的备忘 Agent，建立评测基线 → 诊断问题 → 优化 → 复测对比。
> 所有结果均为**真实模型**（DeepSeek `deepseek-flash`）运行，非 Mock。

## 一、运行配置

| 项 | 值 |
| ---- | ---- |
| 模型 | DeepSeek `deepseek-flash`（OpenAI 兼容，`https://api.deepseek.com`） |
| Agent 框架 | agent-framework 1.23.0 / agent-framework-ag-ui 1.7.0 |
| 评测脚本 | `tests/agent/evaluate.py`（直接调 `agent.run()`，安全用例走 HTTP） |
| 用例集 | `tests/agent/cases.py`，10 个用例，覆盖 7 类场景 |
| 测试数据 | 虚构用户 `eval_user` + 4 条虚构备忘录（脚本每次重置，保证可重复） |
| 运行方式 | `./venv/Scripts/python.exe -m tests.agent.evaluate --label <baseline/after>` |

## 二、基线结果（优化前）

**功能通过：10/10**，但暴露出 3 个质量问题（都是「通过但不理想」）：

| 用例 | 场景 | 基线表现 | 问题类型 |
| ---- | ---- | ---- | ---- |
| C07 | 信息不足（"帮我找一下那个东西"） | 追问了，但**一次性列出全部 4 条** | 回答质量 |
| C08 | 超范围（"帮我删掉这条"） | 说明了只读边界，但**多余调用 `search_my_memos`** | 工具选择 |
| C09 | 工具异常（模拟 DB 故障） | 正确报错，但**同一工具被重复调用 2 次** | 重试策略 |

基线汇总：通过 10/10，**工具调用正确 4/5**，平均耗时 2.23s。

> 工具正确率 4/5 正是被 C08 拉低的（期望不调用工具，实际调用了）。

## 三、问题分析与改动

三个问题的共同根因：**Agent 指令（instructions）只写了能力范围和安全约束，没有写「按场景怎么交互」**。因此按任务要求「每次只改一类主要因素」，本次只改指令，不改工具、不改前端。

| 问题 | 现象 | 原因判断 | 改动（新增交互规则） |
| ---- | ---- | ---- | ---- |
| C07 | 含糊请求时倾倒全部备忘录 | 指令未说明「信息不足先追问」 | 规则 7：请求含糊时先用一句话追问，不要一次性列出全部 |
| C08 | 删除请求多余调用查询工具 | 指令未说明「写入类请求直接拒绝、不必确认」 | 规则 8：要求修改/删除时直接说明只读、不调用任何工具 |
| C09 | 工具故障时重复调用 | 指令未说明「工具报错不要重试」 | 规则 9：工具报错时不重复调用，直接说明失败并建议稍后重试 |

改动落点：`app/agent/memo_agent.py` 的 `AGENT_INSTRUCTIONS`，新增 3 条「交互规则」。

## 四、复测对比（优化后）

### 全量 10 个用例

| 指标 | 基线 | 优化后 | 变化 |
| ---- | ---- | ---- | ---- |
| 用例通过 | 10/10 | 10/10 | 持平 |
| 工具调用正确 | 4/5 | **5/5** | ✅ +1 |
| 平均耗时 | 2.23s | **1.69s** | ✅ -0.54s |
| C07 信息不足 | 列出 4 条 | **追问且未倾倒** | ✅ 改善 |
| C08 超范围 | 多余调工具 | **未多余调用** | ✅ 修复 |
| C09 工具异常 | 重复调用 2 次 | **调用 1 次** | ✅ 修复 |

### 关键用例重复 3 次（排除单次波动）

| 用例 | 基线（3 次） | 优化后（3 次） | 结论 |
| ---- | ---- | ---- | ---- |
| C07 | 0/3 未倾倒 | **3/3 未倾倒** | 稳定改善 |
| C08 | 0/3 未多余调用 | **3/3 未多余调用** | 稳定修复 |

> 重复验证说明：这三个问题在基线是**每次必现**，优化后是**每次都不出现**，不是单次波动。

## 五、限制与未解决问题

1. **检查逻辑依赖关键词匹配**：开发中曾出现 3 次误判（把"哪一条"当成没追问、把"未能完成"当成没说明失败），说明纯关键词判定的鲁棒性有限。当前已补充同义词，但仍不是语义级判断。
2. **样本量小**：10 个用例只覆盖主要场景，不能代表全部真实使用。
3. **模型随机性**：只对 3 个关键用例做了 3 次重复，其余用例单次运行；真实提升幅度可能有小幅波动。
4. **未探索其它优化方向**：本次只改指令，未尝试「工具描述/参数校验」「上下文压缩」「前端错误提示」等方向，无法判断叠加效果。
5. **前端未改动**：Agent 失败时的前端提示沿用了 CopilotKit 默认行为，未做定制。
6. **容器复现未验证**：本机无 Docker，容器化配置已写但未实测。

## 六、复现步骤

```bash
cd memo-backend
# 1. 确认 .env 中有 DEEPSEEK_API_KEY
# 2. 确保后端服务在 8000 端口运行（C10 安全用例需要）
./venv/Scripts/python.exe -m uvicorn app.main:app --port 8000

# 3. 跑基线 / 复测（脚本会自动重置测试数据）
./venv/Scripts/python.exe -m tests.agent.evaluate --label baseline
./venv/Scripts/python.exe -m tests.agent.evaluate --label after

# 4. 关键用例重复 3 次
./venv/Scripts/python.exe -m tests.agent.evaluate --label baseline-repeat --cases C07,C08,C09 --repeat 3
./venv/Scripts/python.exe -m tests.agent.evaluate --label after-repeat --cases C07,C08,C09 --repeat 3
```

结果文件：`tests/agent/results/<label>.json`（完整）与 `<label>.md`（报告）。

## 七、复盘

- **最有价值的一项优化**：规则 8（写入类请求直接拒绝、不调工具）。它同时让「工具选择」从 4/5 提到 5/5，并让响应更快——因为少了一次无意义的查询，属于「既正确又省资源」的改动。
- **一个未解决问题**：评测的判定仍靠关键词匹配，不是语义判断；遇到表达变体容易误判，这是当前评测体系最需要改进的地方。
- **一次未达预期的经历**：第一次优化 C07 后复测反而判失败，排查发现不是 Agent 退化，而是检查函数的关键词表漏了「哪一条」「关键词」这些同义表达。这件事提醒我：**改完先怀疑评测本身，再看模型**，否则会把评测 bug 当成模型问题去改指令。
