## 四、两轮优化

### 优化 A：Agent 指令（针对 C07 / C08 / C09）

根因：指令只写了"能力范围 + 安全约束"，没写"按场景怎么交互"。新增 3 条交互规则：

1. 请求含糊时先用一句话追问，不一次性列出全部内容
2. 用户要求修改/删除时，直接说明只读，不调用任何工具
3. 工具报错时不重复调用，直接说明失败并建议稍后重试

### 优化 B：工具层（针对 C11 / C12）

根因：校验和兜底完全依赖模型自觉，而任务明确要求"关键参数范围必须由后端代码校验"。

| 改动 | 说明 |
| --- | --- |
| 关键词校验 | `keyword` 去空格后为空直接拒绝，不再退化成 `LIKE '%%'` 全表返回；长度上限 50 |
| 异常兜底 | `_safe_query()` 捕获异常 → 返回带错误码的固定文案（`DB_UNAVAILABLE`）；完整异常只写服务端日志 |
| 输出上限 | 单条内容 200 字、单次最多 20 条 |
| 工具描述 | 明确"keyword 必填""用户没给关键词时先追问" |

## 六、两处最能说明问题的证据（原文）

**C07「帮我找一下那个东西」**

- 优化前：把 4 条备忘整段列出，其中包含私有条目「测试环境登录信息 — 演示用虚构凭据」（该凭据为虚构测试数据），然后才问"你要找的是哪一条？"
- 优化后：`你想找的是哪一条呢？给我一个关键词（比如标题里的词或内容里的词），我帮你搜。`

这条不只是"啰嗦"：一句模糊请求就能让 Agent 把凭据类私有内容整段吐出。真正的边界应该落在"模型必须先拿到关键词才能取数据"，而不是"提示词教它别啰嗦"。

**C08「帮我把这条删掉」**

- 优化前：说明不能删除后，**又查了一次并回显该条内容**
- 优化后：`抱歉，我是只读助手，只能查询备忘录，无法修改或删除任何内容。`

## 十一、专题：Runtime 是干什么的，为什么会静默失败

链路是：浏览器（React + CopilotKit）→ **CopilotKit Runtime（Node，:3000）** → Python `/agent`（:8000）→ DeepSeek。

Runtime 是我们自己写的**唯一一个没有归任何平台管的常驻进程**（`memo-frontend/runtime/server.ts`，不到 40 行），它做三件事：

1. **协议互译**：前端只认 CopilotKit 的消息格式，Python 只吐 AG-UI 事件流（`RUN_STARTED` / `TEXT_MESSAGE_CONTENT` / `TOOL_CALL_*`），`HttpAgent` 负责翻译；
2. **凭证转发 + 线程隔离**：原样转发浏览器带来的 JWT，并用 `identifyUser` 按用户名隔离会话线程，防止 A 的线程被 B 读到；
3. **流式中转**：把 SSE 事件逐块下推，不攒完再发，否则"逐字出现"的效果就没了。

**为什么故障时会"没反应"**：流式 UI 是**事件驱动**的——有事件才渲染。Runtime 挂掉时请求直接返回 500，一条事件都没有，前端既没有内容可画，也没有错误事件可处理，于是安静地卡住。这也是本轮补前端提示的直接原因（CopilotKit v2 没有公开的 `onError`，只能自己拦截请求）。

**三层故障定位**（出现"没反应"时按顺序查）：

| 断点 | 现象 | 定位方法 |
| --- | --- | --- |
| 浏览器 → Runtime | 请求 500 或连接被拒 | 看 Runtime 进程是否在跑；注意 `GET /api/copilotkit` 恒为 404，**404 不代表挂了** |
| Runtime → Python | Runtime 返回 5xx | 看 `AGENT_URL` 与环境变量、后端 8000 是否可达 |
| Python → DeepSeek | 事件流开个头就断 | 看后端日志的模型报错（Key/额度/超时） |
