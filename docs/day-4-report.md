## 一、工作概述

本日不新增功能，目标是回答一个问题：**当前 Agent 的表现到底怎么样，哪里不行，改完是否真的变好**。

方法分四步：设定评测用例 → 在改动前完整测一遍（下称"基线"）→ 针对暴露的问题分项改进 → 用同一套用例复测对比。

全程使用真实模型（DeepSeek），测试数据为虚构数据，脚本可重复运行，结论可复核。

## 三、关键数据

| 指标 | 改进前 | 改进后 | 说明 |
| --- | --- | --- | --- |
| 用例通过率 | 10/12（83%） | **12/12（100%）** | 原有功能无退化 |
| 工具调用正确率 | 4/5（80%） | **5/5（100%）** | 该调则调、不该调则不调 |
| 关键问题稳定性 | 0/3 | **3/3** | 同一用例重复 3 次，排除单次波动 |
| 补充场景（多轮、零备忘、超长、注入、并发） | 未覆盖 | **6/6 通过** | 本轮新增 |
| 平均响应时间 | 1.75 秒 | 1.00 秒 | 观测波动较大，**不作为成果结论** |

> "基线"指改动前在固定条件（同一代码版本、同一模型、同一数据、同一用例）下的一次完整测量，用于和改动后对比。条件任一变化，前后数据即不可直接比较。

## 四、发现并解决的主要问题

| 问题 | 实际影响 | 处理方式 | 状态 |
| --- | --- | --- | --- |
| 用户提出模糊请求时，Agent 直接列出全部备忘 | 一句含糊的话就可能把**私有凭据类内容整段输出**，属信息安全风险 | 改为先用一句话追问关键词，拿到关键词再查询 | 已解决 |
| 用户要求删除/修改时，Agent 仍查询了一次数据 | 多一次无效调用，且回显了不该回显的内容 | 改为直接说明"只能查询、不能修改"，不发起查询 | 已解决 |
| 检索关键词为空时，等于查询全部数据 | 存在**越权读取全量数据**的隐患（绕过"按关键词查询"的预期边界） | 在后端代码层拦截空关键词，不再依赖模型自觉 | 已解决 |
| 数据库异常直接抛给上层，错误形态不可控 | 可能向用户暴露技术细节，体验差 | 统一兜底为固定错误提示，技术细节只写服务端日志 | 已解决 |
| 助手服务不可用时，界面无任何提示 | 用户只看到自己发的消息，无法判断是卡住还是故障 | 前端增加可读提示与排查方向，恢复后自动消失 | 已解决 |

其中第一项和第三项属于**安全边界**问题，收益大于体验优化，是本轮最有价值的两项改动。

## 五、质量与安全验证

| 验证项 | 结果 |
| --- | --- |
| 未登录访问 Agent 接口 | 返回 401，且在调用模型前即被拒绝 |
| 用户数据隔离 | 工具仅按登录身份取数，模型与浏览器均无法指定他人 |
| 工具权限 | 只读，无新增任何写入/删除能力 |
| 密钥保护 | 密钥仅存服务端环境变量，不进入代码、日志与评测产物 |
| 原有功能回归 | 登录、退出、备忘增删改查、流式对话均正常 |
| 服务故障表现 | 助手不可用时给出明确提示，不再静默 |
